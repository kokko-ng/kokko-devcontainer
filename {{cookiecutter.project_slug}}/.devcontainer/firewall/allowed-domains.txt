# Hosts the devcontainer may reach (devcontainer-firewall). One per line. The
# firewall allows the addresses a name resolves to, added as they are looked
# up; an entry also covers the names under it, and `*.example.com` says that
# is what it is for (example.com and its subdomains; not resolved at start).
# GitHub's own address ranges are added on top from api.github.com/meta.
# `devcontainer-firewall --blocked` lists hosts that were refused.
#
# Baked into the image: edit this file, then rebuild (dev rebuild) to apply.
#
# What belongs here. The firewall's job is to stop a misled agent sending data
# to a host someone else controls, so an entry must be one of:
#   - a vendor's own service or read-only content (registries, docs, CDNs of
#     published packages, sign-in pages), where nobody else can stand up a
#     receiver under the name;
#   - a cloud namespace whose names are regions or that only accepts this
#     user's Entra ID sign-in (Speech regions, Key Vault);
#   - one of your own resources, by its exact name.
# Never a namespace where anyone can create a host that accepts data: storage
# accounts (*.blob.core.windows.net), web apps (*.azurewebsites.net), API
# gateways, telemetry ingestion, tunnels, paste and file-sharing sites, or
# serverless hosting (*.workers.dev, *.vercel.app, *.netlify.app). Add your
# project's own resources by exact name instead, in the last section.
# The exceptions are marked "EXCEPTION" below: Claude Code's own download
# bucket, and Azure namespaces every project here deploys to daily. For those,
# the auto mode classifier's exfiltration rules, not this list, stop data going
# to someone else's resource. Replace them with exact names where you can.
